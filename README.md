# Enterprise AI Workspace · 企业 Agent 工作台原型

**探索一个自然语言任务入口：发起任务、查看过程、中断后继续，并核对引用的资料来源。**

项目围绕本地项目、Outlook 邮件和飞书文档之间的资料任务展开。我基于官方 Codex SDK/runtime，实现本地命令行入口、任务记录与恢复、连接身份和只读资料工具，并建立结果核验流程。

当前交付形态是单用户本地 CLI。已有任务历史、过程记录、取消与续接能力；企业资料读取代码已接入，真实账号的正文读取验收仍待完成。

## 我的贡献

| 关键问题 | 我的设计与实现 |
| --- | --- |
| 怎样把模型结束与用户验收区分开 | 分开记录执行轮次与任务状态；模型结束后进入待验收，由用户确认任务完成 |
| 退出或中断后怎样继续 | 保存任务、会话与历史，支持续接；分别记录失败、超时、取消和异常中断，拒绝同任务并发执行 |
| 资料访问怎样关联到正确身份与来源 | 实现连接身份、OAuth 接入路径、只读工具范围和来源访问记录，将凭据与任务记录分开保存 |
| 怎样独立核对代码修复结果 | 在模型执行后重新运行测试，核对文件哈希与改动范围，保留验收报告 |

**集成范围：** 我的实现集中在应用服务、交互与连接器；模型调用和底层代码执行复用官方 Codex SDK/runtime。

## 成果与验证范围

- 已实现本地任务服务、历史查询、取消与恢复、连接身份和四个只读 MCP 工具。离线验证覆盖任务状态、并发约束、身份关联与读取接口。
- 历史真实调用证明了对话恢复和连接状态工具可用；Outlook/飞书正文读取及跨来源任务仍待真实账号授权与验收。
- 当前没有 Web UI、企业身份与多租户隔离，也没有外部写入审批链路。资料工具只读，不发送邮件或修改飞书文档。
- 配置隔离和本机身份检查属于单机原型范围。历史原始日志未随仓库公开，代码修复样本也尚未作为跨机器 Demo 分发。
